The more data you're encoding, the higher version you need and the more modules get packed in. More modules means either a larger physical code or smaller individual modules that are harder for cameras to resolve.
Your URL "popcycle.io/track/KT6U89HL" is pretty short at 29 characters, which means you're probably generating a Version 3 or 4 QR code with maybe 29x29 or 33x33 modules. Error correction is the other piece. QR codes have four levels - L (Low, 7% recovery), M (Medium, 15%), Q (Quartile, 25%), and H (High, 30%). Higher error correction means the code can be partially damaged or obscured and still scan, but it also requires more modules for the same data. You're probably using M or Q level, which is the sweet spot for reliability without bloating the code size.
Modern phone cameras have gotten dramatically better at close-focus and image processing, which is why codes that would've been unscannable five years ago work fine now. The software does edge detection and perspective correction automatically, so even slightly worn or angled codes usually scan.

I. Overview & Strategic Positioning
PopCycle is a design studio operating in the medium of post-consumer recycled plastic, specifically HDPE collected primarily from milk jugs. We are not positioned as a recycling company that makes products, but as a design studio that transforms waste streams into tracked, designed objects with complete provenance documentation.
Our competitive differentiation lies not in the plastic itself, but in the infrastructure we've built around it: comprehensive material tracking from collection to customer, a network of community partner organizations providing material supply, and relationship facilitation that creates value flows between organizations that wouldn't otherwise connect.
The Reverse Amazon Model
We've optimized the removal and waste management side of the supply chain with the same rigor Amazon applied to delivery. Every bin is tracked, every batch documented, every item coded with QR provenance. This infrastructure transforms commodity waste plastic into premium design objects where the story, accountability, and verified partnerships justify 3-5x pricing over generic recycled products.
The Guptian Framework
Our business model follows Vinay Gupta's infrastructure thinking: build systems where everyone pursuing their own self-interest creates positive externalities for others. Community partners want visibility and validation. Retailers want authentic sustainability stories. Venues want mission-aligned community impact. We facilitate value flows between these entities, with waste transformation as the mechanism rather than the goal people need convincing to care about.

B. Processing Workflow
Material Cleaning:
Two-stage ultrasonic wash system to handle contamination without depending on perfect source separation.

Initial sort by material type and color, cut out adhesive sections for separate batch treatment
First ultrasonic wash with detergent cycling
Fan-dry on mesh tables
Shred to flakes
Soak in isopropyl alcohol (30 min) and d-limonene (15 min) to dissolve remaining adhesives
Second ultrasonic wash to remove solvent residue
Final rinse and dry
Press into sheets

This workflow prioritizes quality output over speed, ensuring virgin-quality finished products from contaminated input.
Pressing & Inventory:

Heat press creates 2-4mm thick sheets
Temperature kept at minimum viable to avoid degrading trace contaminants into visible defects
Each pressed sheet photographed for online blank selection (D2C)
Sheets stored as universal inventory - nothing produced until ordered
Material genealogy tracked: Gen 1 (virgin collection), Gen+ (production offcuts recycled)

Production:

UV laser for QR codes, logos, text, detail work (~$5K equipment investment needed)
CNC for cutting shapes from sheets
Minimal hand-finishing (deburring, polishing as needed)
Assembly for sets (adding holders, packaging)

IV. QR Code & Tracking System
A. QR Code Generation
URL Structure:

Encoded URL: popcycle.io/track/[PRODUCT_ID]
Product ID: 8-character alphanumeric (Base36 encoded)
No https:// prefix to minimize QR complexity

Generation Process:

Product created in database, assigned unique ID
Generate QR code SVG using qrcode npm package
Store QR data URL in Products collection
Render QR code in laser vector file at specified position

Technical Implementation:
javascriptimport QRCode from 'qrcode';

async function generateProductQR(productId) {
  const trackingUrl = `popcycle.io/track/${productId}`;
  
  const qrSvg = await QRCode.toString(trackingUrl, {
    type: 'svg',
    errorCorrectionLevel: 'M',
    margin: 1,
    width: 256
  });
  
  return {
    qrCodeDataUrl: qrSvg,
    trackingUrl: `https://${trackingUrl}`
  };
}
Size Requirements:

Minimum scannable size: ~6mm (0.25 inches)
Standard size for coasters: 8-10mm
Larger items (cutting boards): 12-15mm

V. File Generation System
A. Vector File Workflow
For D2C Orders:

Customer completes order, selects template and enters text
Backend generates order record
File generation endpoint triggered:

Loads template vector file
For each item:

Generates unique product ID and QR code
Places QR code at template-defined position
Renders text at template-defined position with specified font


Combines all elements into single vector


Outputs:

Laser file (SVG): QR codes + text for all items
CNC file (DXF): Shape outlines for all items



Technical Requirements:

Node library for vector manipulation: svg-path-parser, dxf-writer
Font rendering: Use web-safe fonts or embed subset
Coordinate system must match CNC/laser workspace

C. Generation Code Structure
javascriptasync function generateOrderFiles(orderId) {
  const order = await getOrder(orderId);
  const template = await getTemplate(order.templateType);
  
  // Generate laser file (QR + text)
  const laserSvg = await generateLaserFile({
    template,
    items: order.items.map((item, idx) => ({
      ...item,
      qrCode: generateQRSVG(item.productId),
      position: template.items[idx].position,
      qrPosition: template.items[idx].qrPosition,
      textPosition: template.items[idx].textPosition
    }))
  });
  
  // Generate CNC file (shapes only)
  const cncDxf = await generateCNCFile({
    template,
    items: order.items.map((item, idx) => ({
      shapeFile: template.items[idx].shapeFile,
      position: template.items[idx].position
    }))
  });
  
  // Upload to storage
  const laserUrl = await uploadFile(laserSvg, `orders/${orderId}/laser.svg`);
  const cncUrl = await uploadFile(cncDxf, `orders/${orderId}/cnc.dxf`);
  
  // Update order
  await updateOrder(orderId, {
    laserFile: {url: laserUrl, generatedAt: new Date()},
    cncFile: {url: cncUrl, generatedAt: new Date()},
    status: 'files_ready'
  });
  
  return {laserUrl, cncUrl};
}
